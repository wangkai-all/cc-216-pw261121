# 公交票价规则历史回放（分析沙盒）

在网页上用**历史刷卡事件**回放票价规则，按用户还原可计费行程，并比较不同候选规则方案的结果。

> ⚠ **仅用于分析**：所有卡号、线路、站点均为虚构数据；导出内容统一标注 `*_ANALYSIS_ONLY`，是分析结果而非真实扣款。系统不连接任何支付通道，不产生资金变动。

## 运行

无需构建步骤，原生 ESM + 浏览器加载：

```bash
# 任选一种静态服务器
python3 -m http.server 8080
# 或：npm run serve
```

打开 <http://localhost:8080/index.html>，首次进入会自动载入虚构示例数据并完成首次计费。

运行测试（纯 Node，无需浏览器）：

```bash
npm test
# 即 node --test 'tests/**/*.test.js'
```

测试共 20 个：引擎规则 13 个、端到端 1 个、导入解析 5 个、jsdom 页面冒烟 1 个。

## 六步工作流

| 标签 | 能力 |
| --- | --- |
| ① 数据导入 | JSON/CSV 刷卡事件导入（支持中文表头别名）、票价方案导入、模板下载、事件清单 |
| ② 规则编辑 | 两套候选方案 A/B；一票制/里程票价、带生效时间；换乘/日封顶/周封顶规则增删改与优先级调整；缺下车策略；时区与周起始日 |
| ③ 行程回放 | 按卡号还原可计费行程；每程可展开完整计价依据（基础票价、换乘减免、日/周封顶调整及累计值）；日/周累计表 |
| ④ 重算与差额 | 模拟离线补传、撤销刷卡；快照历史只追加不覆盖；输出与原扣费的逐笔差额、新增/消失行程、受影响业务日/周 |
| ⑤ 方案对比 | 同一批出行在两套规则下的逐程基础/最终费用、总额差，各自依据可分别展开 |
| ⑥ 分析导出 | JSON / CSV 分析结果导出（含免责声明与 exportKind 标记）、重算差额导出、工作区快照 |

数据保存在浏览器 `localStorage`，刷新不丢失。

## 核心业务语义

### 时间与边界

- **业务时区可配置**（默认 `Asia/Shanghai`）。日桶、周桶、规则生效时间都按业务时区**墙钟时间**计算。
- 行程以上车时刻归桶：跨午夜的行程归入上车日；周日深夜跨周界的行程归入原周，不被边界切断。
- 换乘窗口按**绝对时刻**计算经过分钟数，因此跨午夜换乘在窗口内仍有效。
- 周桶键为该周的周起始日（默认周一，可改周日/周六）。

### 行程重建（`src/core/trips.js`）

状态机按卡号、时间排序配对 `BOARD → ALIGHT`：

- 连续两次 `BOARD`：前一程标记 `MISSING_ALIGHT`，**不假设行程完整**。
- 无配对的 `ALIGHT`：记为孤儿下车异常并忽略。
- `CANCEL` 事件通过 `cancelEventId` 使原刷卡失效，之后整体重新配对。
- 行程身份基于上车事件，补传下车后身份不变，因此重算能对上同一物理行程。

### 缺少下车记录（两种可配置策略）

- `PENDING`：进入待处理，不计费、不参与日/周封顶累计、不作为换乘依据，待补全后重算。
- `DEFAULT_FARE`：按约定补扣额计费；留空则取该线路最高档票价。补传真实下车后重算，差额单独保留。

### 计费管线（`src/core/engine.js`）

金额内部一律用整数**分**，杜绝浮点误差。每个计费行程按规则 `priority` 升序依次执行：

1. 基础票价：一票制，或按线路站序差匹配里程档位（取能覆盖乘车站数的最小 `maxStops` 档，不依赖书写顺序）。
2. `TRANSFER` 换乘优惠：窗口内、可选限同线路，支持百分比/固定减免与封顶折扣上限。
3. `DAILY_CAP` 日封顶：当日累计（已应用前置优惠后的实付）超封顶时，只对当程调整到剩余额度，不产生负扣费。
4. `WEEKLY_CAP` 周封顶：同理按周桶累计。

每条规则都可带 `effectiveFrom/effectiveTo`（业务时区墙钟），在行程上车时刻不生效则跳过；同线路多条票价同时生效时取最近生效的一条。每一步都写入 `evidence`，UI 可展开看到规则 ID、计算细节与封顶前累计值。

### 重算与差额（`src/core/recompute.js`）

- 每次计算保存不可变快照（事件全集 + 结果 + 差额），保留最近 30 次。
- 通过事件指纹对比自动定位受影响卡号，只对这些卡号输出差额；未受影响卡号结果不变。
- 同一物理行程前后扣费不同 → `changedTrips`（带 `deltaCents`，正=补收、负=退回）；新出现/消失的行程单独列示，不伪造差额。
- 同时汇总受影响卡号在各业务日/周的最新累计，说明封顶周期的波及范围。

## 目录结构

```
src/core/        纯函数引擎（无 DOM 依赖，可直接 Node 测试）
  money.js       分/元换算
  time.js        业务时区墙钟、日/周桶、生效时间
  csv.js         CSV 解析/序列化
  trips.js       刷卡事件 → 行程状态机
  engine.js      票价匹配 + 优惠/封顶管线 + 双方案对比
  recompute.js   快照账本与差额
src/web/         浏览器 UI（原生 ESM，无框架、无构建）
tests/           node:test 测试
index.html       页面外壳
```

## 导入数据格式

事件 CSV 表头（JSON 字段同名，支持中文别名）：

```
eventId,cardId,routeId,eventType,stopId,ts,uploadedTs,cancelEventId,source
```

- `eventType`：`BOARD` / `ALIGHT` / `CANCEL`（或 上车/下车/撤销）
- `ts`：ISO 8601，建议带时区偏移；`uploadedTs` 晚于 `ts` 即表示离线补传
- `CANCEL` 行通过 `cancelEventId` 引用被撤销的原事件，允许无 `ts`
